Reglas de Oro para Desarrolladores Motor Único de Validación (MUV) — Validación en tiempo real

El IHCE validará en tiempo real el contenido JSON usando su MUV. Implementar estas reglas es obligatorio para evitar errores HTTP 400 y 409.

Cruces contra EVOL (Registraduría Nacional)

El sistema rechazará el JSON si el recurso Patient no coincide exactamente con el registro nacional EVOL en:

@for (field of ['Tipo de ID', 'Número de ID', 'Sexo biológico', 'Primer nombre', 'Primer apellido']; track field) { {{ field }} }

Excepción: Para extranjeros sin documento colombiano oficial o pacientes no identificados en emergencia, se omite EVOL pero se valida contra la existencia previa en el sistema.

Prevención de Duplicados HTTP 409

Se rechazará el envío si un Encounter tiene exactamente los mismos campos de uno ya existente:

@for (field of ['subject (paciente)', 'period (fecha/hora)', 'serviceProvider (prestador)', 'participant (médico)']; track field) {
{{ field }}
}

Referencias Internas con Numeral (#)

Cuando un recurso apunte a otro dentro del mismo Bundle, la referencia usa #TipoRecurso-NumRecurso. El ID declarativo del recurso no lleva numeral.

Terminologías Mapeadas

No se pueden enviar códigos internos del software propio. Todos los envíos deben usar exclusivamente:

@for (term of terminologias; track term.code) {
{{ term.code }} {{ term.desc }}
}

Validación RETHUS en Tiempo Real

Los documentos de los médicos tratantes enviados en el recurso Practitioner se validarán contra la base nacional RETHUS. Si el médico no está activo, se rechaza la transmisión completa.

Recomendación: Usar el endpoint POST /Practitioner/$consultar-profesional-salud antes del envío para verificar estado.

Políticas de Encolamiento (Store-and-Forward)

Dado que prestan servicios a domicilio sometidos a caídas de internet móvil, se exige técnicamente:

  • Mecanismo asincrónico con backoff exponencial
  • Las atenciones sin conexión deben encolarse localmente
  • Reintentar envío cuando el dispositivo retome conexión
  • Registro (log) claro de intentos y errores de estructura

Tecnologías sugeridas: RabbitMQ, Kafka, Azure Service Bus, o IndexedDB (en caso de app móvil).
